# WebView 验证说明

构建脚本执行 URL 白名单、登录门禁、DOM 投影、分区刷新、切换、退出隔离和京东订单识别回归，并校验 DEX、APK 对齐、签名及包版本。

身份码亮度回归覆盖未加载图片、隐藏内容、屏幕外内容和可见身份条码。只检查展示节点与可见性，不读取码值或凭据。

发布前应在设备上验证：

1. 官方登录、身份码显示、刷新及过期更新。
2. 底栏点击、拖动、快速连续切换时标题清晰且页面状态保留。
3. 身份码出现时提亮，滚出可视范围、切页、弹窗、后台及锁屏后恢复原窗口亮度。
4. 淘宝、拼多多与京东独立退出，再次登录及重启后的会话行为。
5. 有实际待取包裹时核对取件码，并在驿站验证扫码。

自动化检查不代替真实账号、平台风控和扫描设备的端到端验收。上游 H5 结构变化可能影响展示与识别。

## 0.8.3（2026-11-19）

- 正式构建通过 7 组 Java 回归与 20 项 JavaScript/DOM 回归；APK 为 0.8.3 / versionCode 37，关闭调试，通过 v2/v3 签名校验，签名证书与 0.8.2 一致。
- 在真机（PKW110）真实京东商城到站包裹（邮政派送至校内驿站，订单摘要未含具体数字取件码）上实测：能够识别到站状态、展示驿站名与商品缩略图，并通过 `openapp.jdmobile://virtual`（`des: "orderTrack"`）直达京东 App 原生「待取件」页面。
- 实测京东接口返回「大促异常火爆 / 服务繁忙」限流提示时，不再误显示为“暂无待取包裹”，而是提示“取件信息暂未更新 / 京东订单页面当前繁忙，请稍后点刷新重试”。
- 新增 `promptInfo`（`content` + `variableList`）与扩展取件码/货架号规则已通过本地 JS/DOM 回归验证；真实带短码的京东自提柜订单仍待后续实际场景补充。
- 测试截图、手机号与设备信息不进入版本控制与 Release 附件；附件仅包含正式 APK 及 SHA256 校验文件。

## 0.8.2（2026-11-15）

- 正式构建通过 7 组 Java 回归与 20 项 JavaScript/DOM 回归；APK 为 0.8.2 / versionCode 36，关闭调试，通过 v2/v3 签名校验，签名证书与 0.8.1 一致。
- 京东官方登录表单使用链接式按钮，旧协议拦截规则会吞掉「同意协议并登录」点击。新增回归覆盖登录按钮、嵌套文字、一键登录、确认区域中的提交操作，以及仍须拦截的协议正文链接。
- 淘宝回归覆盖控件已挂载但隐藏、仅由样式变化显示的场景；表单未就绪时继续保持加载期限，成功绘制后再结束期限。没有通过放弃主题绘制等待来绕过加载问题。
- 用户已反馈京东短信验证登录成功；本轮未代用户填写或提交验证码。该反馈与自动化回归分别记录，不据此推断所有设备和网络条件均已覆盖。
- 测试截图、验证码、手机号和设备连接信息不随代码或发布附件上传；附件仅包含正式 APK 及 SHA256 校验文件。

## 0.8.1（2026-11-14）

- 正式构建通过 7 组 Java 回归与 20 项 JavaScript/DOM 回归；APK 为 0.8.1 / versionCode 35，关闭应用及 WebView 调试，通过 v2/v3 签名校验并沿用既有证书。
- 正式 APK 已覆盖安装并冷启动；没有为验证清除真实账号数据。升级后仍需登录的场景不等同于所有官方会话都能永久保留。
- 本轮开发中核对了四个平台首次加载身份码高度、淘宝空包裹居中、菜鸟刷新尺寸与京东刷新文字位置；京东官方身份码曾在真机展示、刷新和旋转放大。
- 淘宝昼夜交接检查采集 534 个窗口画面样本，覆盖点击、两个方向的拖动及拖回取消。正常单向切换未测到颜色反向跳变；取消手势按预期返回原配色。窗口采样不代表所有设备、WebView 或网络条件均已覆盖。
- 淘宝登录页在真机检查了手机号阶段的配色、区号和显示交接；验证码阶段完成结构与配色测试，此次没有实际发送短信。
- 拼多多官方登录页已在独立测试环境检查下方提示位置及进入手机登录表单后的布局，没有重用或清除用户账号来做该项测试。
- 没有待取的京东商城订单，真实订单取件码、驿站扫码和完整到期更新周期仍待实际场景验证。
- 真机截图、录屏、日志及研究中间文件不进入版本控制与 Release 附件；发布附件仅为 APK 及 SHA256 校验文件。
