# 应用图标原理

日期：2026-10-28（北京时间）。对应版本 0.7.5 Release（versionCode 30）。

图标采用用户选定的方案 2「圆角底板版」：奶油色圆角底板 + 深红描边，角色抱快递箱。源图保存在 `design/icon-candidates/icon-02.png`（1254×1254 RGBA），生成提示词见同目录 `PROMPTS.md`。

## 一、资源组成

| 文件 | 作用 |
| --- | --- |
| `drawable-nodpi/ic_launcher_artwork.png` | 前景位图，512×512 RGBA，由源图等比缩放 |
| `drawable/ic_launcher_foreground.xml` | 前景包装：`<inset>` 四周内缩 13% |
| `values/launcher_colors.xml` | 背景色 `#FCF6E7` |
| `mipmap-anydpi-v26/ic_launcher.xml` | 自适应图标入口，组合上面两层 |
| `AndroidManifest.xml` | `android:icon` 与 `android:roundIcon` 均指向 `@mipmap/ic_launcher` |

`drawable/ic_launcher.xml` 保留为位图兜底，不再被清单引用。

## 二、自适应图标的尺寸模型

Android 8.0（API 26）起，桌面图标由两层 108×108dp 图层合成，系统再套用自己的遮罩：

```text
108dp 图层（背景 + 前景）
 └─ 72dp 可见视口：遮罩至少保留这一块，四周 18dp 可能被裁
     └─ 66dp 安全圆：内容放在这里才保证任何遮罩都不被切
```

因此「图标内容多大」取决于它在 108dp 里占的比例，与位图像素数无关。缩放、密度换算和遮罩都由系统完成。

## 三、13% 内边距的来历

要让深红描边正好落在图标边界上，底板的描边需要压在 72dp 可见视口的边缘。

源图里底板描边矩形为 x 62—1188、y 81—1179，宽 1126px，占画布 1254px 的 89.8%。设内缩比例为 i，则描边落在 72dp 处需满足：

```text
0.898 × (1 − 2i) × 108dp = 72dp  →  i ≈ 12.9%
```

取 **13%**。三种取值的实测差异（真机应用信息页与桌面截图）：

| 内边距 | 底板尺寸 | 表现 |
| --- | --- | --- |
| 19%（≈66dp 安全圆的保守值） | 约 60dp | 底板缩成小徽章，四周留一圈奶油色，红框浮在图标内部 |
| 13%（当前） | 约 71.8dp | 底板填满图标，深红描边贴住四边；实测四边向内 1—3px 均为描边色 `#9B1023` |
| 4% | 约 83dp | 描边整条被遮罩裁掉，只剩角色与奶油底，红框消失 |

背景色取源图底板的奶油色 `#FCF6E7`（实测主色 252,246,231），与底板同色，所以遮罩裁到哪都不会出现接缝，只有描边会因裁切而中断。

## 四、为什么红框无法对所有遮罩都严格贴合

遮罩形状（圆形、圆角方形、泪滴形等）由桌面决定，App 无法获知，也无法让画在位图里的固定形状跟着变形。因此：

- 当前 13% 对齐的是**圆角方形遮罩**，本机桌面即为该形状，四边贴合。
- 换成**圆形遮罩**的桌面，四条直边仍贴合，四角描边会被裁掉一部分。
- 若要求任何遮罩都贴边，只能去掉画好的描边，让遮罩本身成为图标边界；那样也就没有「圆角底板」的外观了。

这是方案 2 的固有取舍，不是内边距可以继续微调解决的问题。

## 五、尺寸与密度适配

- 自适应图标由系统缩放，**一套资源覆盖所有密度和桌面图标尺寸**，不需要 mdpi—xxxhdpi 多套 PNG。minSdk 26，也不需要 pre-26 的 `mipmap-*dpi` 兜底。
- 前景位图取 512px：108dp 图层在 xxxhdpi 为 432px，512 仍有余量，可覆盖到约 128dp 的桌面图标；再大的图标尺寸才会开始插值放大。
- 位图用 `drawable-nodpi` 存放，避免系统按密度再次缩放；实际尺寸由 `<inset>` 与图层边界决定。

## 六、重新生成与修改

改图标只需替换源图后重跑导出，不必改 Java 代码：

```python
from PIL import Image
src = Image.open('design/icon-candidates/icon-02.png').convert('RGBA')
src.resize((512, 512), Image.LANCZOS).save(
    'app/src/main/res/drawable-nodpi/ic_launcher_artwork.png', optimize=True)
```

调整贴边程度时改 `ic_launcher_foreground.xml` 的四个 `android:inset*`，按下式换算：

```text
inset ≈ (1 − 72 / (108 × 底板占画布比例)) / 2
```

底板占画布比例改变（换图）后必须重新计算，否则红框会重新浮起来或被裁掉。

## 七、验证方式

1. `aapt dump badging` 输出中 `application-icon-160` 应为 `res/mipmap-anydpi-v26/ic_launcher.xml`，`application-label` 为 `HandyCode`。
2. 安装后在「应用详情」页看图标，再回桌面看实际遮罩效果；两者图标尺寸不同，可一并确认缩放。
3. 需要像素级确认时，截图后取图标外接矩形，沿四条边的中点向内 1—3px 采样，颜色应为描边色 `#9B1023` 而不是奶油色或发色。
