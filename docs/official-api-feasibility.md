# 个人取件身份码：官方接口核验

核验日期：2026-10-27（北京时间）。

> 本文记录核验日期当天的公开接口调研。菜鸟官方网页入口请参见 README 的「菜鸟身份码」一节。

## 结论

**尚未接通淘宝或拼多多的个人取件身份条形码接口。没有获取真实身份码，也没有生成可用于取件的条形码。**

已查阅的公开官方文档中，未确认存在适用于本项目的「消费者登录 → 获取其当前取件身份条形码」开放能力。拼多多和部分开放平台页面未能读取，不能将检索结果表述为「官方绝对没有接口」。

## 已确认的官方能力与区别

| 官方资料 | 核验结果 | 对本项目的意义 |
| --- | --- | --- |
| 菜鸟物流科技「取件码服务」 | 用运单号与收件人手机号码鉴权，查询某个包裹的取件码 | 属于包裹取件码，公开产品说明没有证明其提供个人身份条形码 |
| TOP API `cainiao.guoguo.courier.graborder.getrealnameinfobyidentitycode` | 请求要提供已有的身份码值、来源、小件员 ID 与 sessionCode；响应为实名信息 | 它消费身份码而非生成身份码，并非本项目所需接口，未调用 |
| 淘宝开放平台授权说明 | 应用登记、用户授权与令牌交换有官方流程 | 通用授权流程存在，不等于身份条形码能力已向该应用开放 |
| 拼多多开放平台 | 搜索与网页读取未获得可核实的个人取件身份码接口文档 | 能力、权限、请求参数及返回值均待确认 |

“接口不需要授权”不等于匿名随意调用。例如上面的 TOP 接口仍列有 AppKey、签名和业务会话参数。普通购物登录状态、商家开放平台授权和驿站/快递员业务身份不可直接等同。

## 验证边界

公开页面可达性不能证明受保护业务接口可用。接口接入需要核实平台授权、业务权限及真实响应，探测脚本只检查无凭据的公开 URL。

## 继续接入的必要信息

首先需要平台提供或确认**个人取件身份条形码**的正式接口文档，至少包含：方法名称、适用主体/场景、消费者授权方式、应用权限申请条件、响应码值与条码制式、有效期与刷新规则。单有 AppKey 或商家订单权限不保证能够获取个人身份码。

若已获相应权限，再配置本项目自己的应用凭据与官方授权，按文档联调真实接口。应用密钥应留在服务端；客户端只接收允许展示的码值与过期时间。当前没有经过确认的接口契约，所以尚未编写虚构的 API 适配器，也未把任意 ID 编成条形码充当取件身份码。

**当前阶段交付是可行性核验，不是可安装的 Android 软件。** 核心数据来源未确认前，不能宣称“不跳转自动亮码”已实现。
