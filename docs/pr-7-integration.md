## 冲突处理

1. **原四页保留 0.8.1 行为。** 不恢复已移除的三态主题、标题栏退出入口或旧骨架加载类，保留身份码、加载高度、玻璃昼夜交接与登录修复。京东身份码及订单页继续由原 `JdPage` 管理。
2. **聚合逻辑独立。** 从贡献版本的 `JdPage` 拆出 `PickupSummaryPage`，容纳淘宝、拼多多、京东订单、顺丰和抖音的汇总。新增 `PickupUrlPolicy`，不放宽原京东页的导航策略。
3. **京东脚本分离。** 原京东页继续使用 0.8.1 的 `jd-orders.js` 及其错误状态契约；新增 `pickup-jd-orders.js` 保留贡献中的订单列表桥接、个人中心回退和进度文案识别，用于实验汇总页。
4. **来源快照只读。** 淘宝、拼多多只向内存中的汇总页提供当前已识别的待取包裹，不为轮询强制刷新或重新投影来源。相同取件码的不同包裹保留独立行；不把孤立的运单号或日期猜成取件码。
5. **登录与退出按平台隔离。** 淘宝与拼多多继续在原页登录，完成后可返回汇总。京东、顺丰、抖音在汇总页中间区域打开各自官方页面。原京东页与汇总中的京东共用系统 WebView 会话；退出其中一处时同步重置两处展示，顺丰与抖音按各自站点清理，不扩大到其他平台。
6. **版本和资源。** 不采用贡献中的 0.8.21 发布元数据；原快捷方式 ID、标签和 HandyCode 应用名保持。保留新增平台图标和汇总图标；原生导航根据五页布局计算。

## 隐私与会话调整

贡献版本中存在额外 Cookie 拷贝、Cookie 延长/恢复、订单 JSON 落盘及原生携带凭据重放抖音请求的逻辑。本集成结果未采用这些路径：

- 不在原生层读取、拼接或复制 Cookie，不保存 Cookie、登录用户对象或订单 JSON 到 SharedPreferences / 单独的 localStorage 键。
- 不在启动、渲染、回退或销毁汇总页时主动清除官方 Cookie / 风控存储；只有用户明确退出对应平台时使用按站点清理能力。
- 不在原生层代发带登录态的业务请求；新增采集器在各自官方 WebView 中观察正常页面响应，保留请求的官方认证流程。
- 顺丰登录、记住登录和到期恢复由官方页面处理。不自行调用 token 签名自动登录，不因“短信成功”或未确认二维码而假定订单已就绪。
- 抖音不复制跨域 Cookie。登录与订单页间的官方会话能否衔接，仍需真机验证；若官方链路不可用，本分支不会用额外凭据搬运来伪造成功。
- 汇总页的订单快照只在当前进程内存中存在。离开汇总标签暂停其轮询；首次访问前不提前创建新的三个平台网页，不影响原四页启动。

这与原贡献的会话实现存在有意差异，不能把原贡献版本的自动登录经验直接视为本集成版本已验证。
